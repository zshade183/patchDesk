# PatchDesk 40 题代码修复评测

题集版本为 repair-v3，真实模型配置为 `deepseek-flash`。保留 12 道原题并新增 28 道，其中 24 道新增题使用单文件仓库，另外 4 道使用双文件仓库。整套题共有 6 道跨文件任务。

新增题覆盖数值计算、CSV 与 Unicode 解析、图搜索、容器状态、缓存和跨文件接口。
每题使用独立 Git 仓库。修复前先确认原有测试通过，并核对独立验收触发该题预期的缺陷。
验收断言独立于任务仓库。离线模式和真实模型各执行一次，每次最多同时运行三个任务。

## 实测结果

| 模式 | 解决数 | 回归通过 | 独立验收通过 | 单题耗时中位数 | 平均轮数 | 整轮耗时 |
| --- | ---: | ---: | ---: | ---: | ---: | ---: |
| 离线固定动作 | 40/40 | 40/40 | 40/40 | 5.14 秒 | 4.30 | 73.49 秒 |
| 真实模型 | 40/40 | 40/40 | 40/40 | 13.45 秒 | 4.45 | 188.95 秒 |

真实模型解决了新增题中的 28/28 道，跨文件题中的 6/6 道。

## 指标口径

- **解决数**统计正常结束、生成非空补丁、通过原有回归测试并通过独立验收的运行。
- **回归通过**统计原有测试通过的运行，衡量补丁对已有行为的影响。
- **独立验收通过**统计满足缺陷修复要求和边界条件的运行。
- **单题耗时中位数**从创建该题仓库计到验证返回，包含模型和网络等待。整轮耗时是全部任务在三并发下的实际墙钟时间。
- **平均轮数**对应执行器记录的模型交互次数，离线为固定动作次数。客户端内部 HTTP 重试不另计。

## 复现

```powershell
.\.venv\Scripts\python.exe -X utf8 -m patchdesk.benchmark --jobs 3
.\.venv\Scripts\python.exe -X utf8 -m patchdesk.benchmark --live --jobs 3 --model deepseek-flash
```

原实验的逐次数据保存在 `.runs/benchmark-scripted.json` 和 `.runs/benchmark-repair-v3-model-pre-usage.json`，其中 run_id 对应每次运行的补丁和测试记录。评测使用合成 Python 任务，每题的在线数据来自一次运行。

## Token 用量复测

使用 deepseek-flash 对同一组 40 道题各重跑一次，最多同时运行 3 道题。解决数为 40/40。以下数据来自主 Agent 各次模型调用的响应。辅助模型调用和无用量响应的服务端消耗不计入。

| 指标 | 实测 |
| --- | ---: |
| 有用量记录的主模型调用 | 173/173 |
| 主模型用量记录完整的任务 | 40/40 |
| 输入总量 | 190,397 |
| 未命中缓存或写入缓存之外的输入 | 35,133 |
| 缓存读取 | 155,264 |
| 缓存写入 | 0 |
| 缓存读取占输入比例 | 81.5% |
| 输出总量 | 41,476 |
| 输入与输出合计 | 231,873 |
| 单题 token 中位数 | 5,181 |
| 每解决一题消耗的 token | 5,796.82 |

输入总量为 API 的常规输入、缓存读取与缓存写入之和。每解决一题的 token 为全批次记录总量除以解决数，分子包含未解决任务的已记录消耗。只有批次内每道题的主模型调用用量都完整时，才计算这个指标。离线脚本和旧版任务的 token 用量为缺失值。用量字段定义见 [DeepSeek Messages API](https://api-docs.deepseek.com/zh-cn/api/create-message/)。

复测的逐题用量在 .runs/benchmark-model.json，每次主模型调用的字段在任务目录的 usage.jsonl。上方原实验的在线记录归档为 .runs/benchmark-repair-v3-model-pre-usage.json。
